# YourArogyum

A web-based preventive-wellness prototype: profile-based diet and workout guidance, an AI wellness assistant, experimental diabetes and heart "risk" estimates with SHAP explanations, and per-user progress records.

> **Not a medical device.** It does not diagnose disease or replace a clinician. The risk models are trained on **synthetic, rule-generated data** and are **not clinically validated**. Wearable values shown in Tracker mode are **simulated demonstration data**.

## Architecture

| Part | Folder | Technology |
|---|---|---|
| Web interface | `src/` | React, TypeScript, Vite, Tailwind CSS |
| Application server | `backend/` | Java 21, Spring Boot 4.1, Spring Security, JPA, MySQL |
| ML service | `ml-service/` | Python, FastAPI, scikit-learn (Random Forest), SHAP |
| Assistant and explanations | `backend/.../service/` | Google Gemini API (`gemini-3.5-flash-lite` configured), `gemini-embedding-001` for retrieval |
| Knowledge base for retrieval | `backend/src/main/resources/health-knowledge/` | one Markdown file, four sections (diet, activity, sleep, type 2 diabetes prevention) |

## Run locally

1. **ML service** (Python 3.12 tested):
   ```bash
   cd ml-service
   python -m venv .venv && source .venv/bin/activate      # Windows: .venv\Scripts\activate
   pip install -r requirements.txt
   python train_model.py            # optional: retrains and overwrites model/*.pkl
   uvicorn app:app --host 127.0.0.1 --port 8000
   ```
2. **Backend**: create `backend/.env` (never commit it) with `DB_URL`, `DB_USERNAME`, `DB_PASSWORD`, `MAIL_HOST`, `MAIL_PORT`, `MAIL_USERNAME`, `MAIL_PASSWORD`, `MAIL_FROM`, `GOOGLE_CLIENT_ID`, and `GEMINI_API_KEY`, then:
   ```bash
   cd backend && ./mvnw spring-boot:run
   ```
   MySQL must be running; Hibernate creates tables on first start (`ddl-auto=update`).
3. **Frontend**: `npm ci && npm run dev` (build check: `npm run build`).

## Reproducing the research results

See [`ml-service/experiments/README.md`](ml-service/experiments/README.md). All reported model metrics regenerate from the code in this repository with fixed seeds.

## Data provenance

- Training data for the risk models are generated by `ml-service/train_model.py`; no real patient data are used.
- The optional real-data experiment uses the public Pima Indians Diabetes dataset (NIDDK); the file is downloaded at run time and is not stored in this repository.

## Known limitations

See the paper's limitations section. Notably: synthetic labels; a very small retrieval knowledge base; no formal evaluation of assistant answers yet; free-tier hosting.

## Backend configuration note

The backend imports `backend/.env` through
`spring.config.import=optional:file:./.env[.properties]` when launched
from the `backend` directory. Use the environment-variable names documented
above. Never commit real credentials or API keys. Check
`backend/src/main/resources/application.properties` for optional settings
and their defaults.
